**What I learned or had to look up**

One of the most valuable things I have learned from my recent AI projects is how different building an AI workflow is from simply making an LLM API call.

While building AI Incident Commander, I had to learn and work with LangGraph orchestration, RAG, retrieval, state management, evidence collection, multiple specialized agents, and handling failures from external LLM services.

I also learned that AI-generated code should not simply be accepted because it works. I review generated code, understand how it fits into the system, rewrite parts when necessary, and debug the underlying problem rather than repeatedly prompting until something happens to work.

Before starting this Buildathon, I also read through the challenge requirements and explored how WhipScribe approaches transcription, recording libraries, AI-powered search/chat, API access, and MCP integration.

What stood out to me is that this challenge is not only about producing code. It evaluates whether I can identify a real problem, make good product and UI decisions, use AI tools critically, finish an end-to-end workflow, and clearly explain the decisions and trade-offs behind what I build.

That is the approach I plan to take throughout the Buildathon.
