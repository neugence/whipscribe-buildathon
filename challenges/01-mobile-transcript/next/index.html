UI challenge 01

Mobile transcript reader, next pass

A quieter reader that keeps the transcript primary, turns bottom controls into one compact dock, and makes every panel feel like the same system.

Reader first One bottom system Progressive actions Designed states

What changed

Remove weight from the reader, not capability from the product.

Bottom controls are now a dock

The preview prompt, audio progress, play controls, and error message are grouped into one compact surface so transcript text is not trapped behind stacked bars.

Panels share one pattern

Search, export, settings, and more use consistent sheets, headers, touch targets, and close behavior instead of each feeling like a separate idea.

Phone-specific decisions

More menu items are grouped by intent, text selection gets contextual actions, and a missing processing state is added for uploads that are not ready yet.
